# Включено по умолчанию (wiki electerm → Anubis-Security-Tool)

Пути указаны относительно `fork\app\src`. Номера строк приблизительные (на момент правки).

| Фича | Wiki-страница | Что включено по умолчанию | Где |
|---|---|---|---|
| Auto data sync | `Auto-data-Sync` | `syncSetting.autoSync = true` (при каждом изменении, направление upload); активная вкладка синхронизации — `cloud`; `cloudApiUrl = brand.sync.cloudApi`. github/gitee/webdav/custom остаются доступными, но без токена/gist id не синхронизируются (`uploadSettingAll` пропускает типы без gistId). | `app/common/config-default.js:22`, `client/store/init-state.js:161`, `client/store/sync.js` (`uploadSettingAll`) |
| Autorun при входе в ОС | `Autorun-electerm-when-login-to-os` | `autoStartOnLogin = true`; `app.setLoginItemSettings({ openAtLogin, args: ['--autohide'] })` на каждом старте и при смене значения. Только в упакованном приложении (в dev не регистрируется). Пользователь может выключить в Settings только если админ разрешил (`ANUBIS_ADMIN_AUTOSTART_USER_CAN_DISABLE=1`), иначе ключ admin-locked. | `app/common/config-default.js:27`, `app/lib/admin-startup.js` (`applyLoginItem`), `app/lib/user-config-controller.js` |

| Secret gist | `Create-secret-gist` | Вкладки github/gitee в Settings → Sync доступны всегда (поля Token и Gist ID). Без токена синхронизация через gist не работает — это ожидаемо; UI не скрыт. | `client/components/setting-sync/setting-sync-form.jsx` |
| Deep link | `Deep-link-support` | `deepLinkAutoRegister = true`: протоколы `brand.protocol.extra` + `anubis://` регистрируются на каждом старте упакованного приложения (`registerDeepLink()`). Кнопка «Unregister» ставит `deepLinkAutoRegister=false` (автоперерегистрации нет), «Register» — снова `true`. | `app/lib/admin-startup.js`, `app/lib/deep-link.js`, `client/components/setting-panel/deep-link-control.jsx` |
| MCP widget | `MCP-Widget-Usage-Guide` | MCP-сервер стартует вместе с приложением (`mcpServerEnabled = true`; если нет сохранённого autorun-элемента, store сам запускает виджет `mcp-server`). Токен (`apiKey`) генерируется при первом запуске (32 байта, hex), хранится в `userData\admin-mcp-token`, не хардкодится; всегда подставляется в main-процессе (нельзя очистить из UI). Токен не отдаётся в renderer (`serverInfo.apiKeyManagedByAdmin`). Хост по умолчанию `127.0.0.1`. | `client/store/widgets.js` (`startAutoRunWidgets`), `app/widgets/widget-mcp-server.js` (`applyAdminMcp`), `app/common/admin-policy.js` (`ensureMcpToken`) |
| Create bookmark by AI / AI chat | `Create-bookmark-by-AI` | `baseURLAI = brand.ai.baseURL` (`https://ai.anubis.locker/api/ai`), `apiPathAI = '/chat/completions'`, `modelAI = 'free'`, `authHeaderNameAI = 'Authorization: Bearer'`. Старый дефолт `https://cf.api.fan/v1` удалён. При admin-lock список пресетов в форме сводится к одному пресету бренда (`window.et.defaultAIPreset`, собирается `build/bin/pug.js` и `build/vite/dev-server.js` из `brand.ai`). Другие места, переопределяющие endpoint по умолчанию, не найдены (`app/lib/ai.js` берёт `defaultSettings.baseURLAI`). | `app/common/default-setting.js:76`, `client/common/default-setting.js:84`, `client/components/ai/ai-presets.js` (`getAIPresets`) |

Замечания:

- Пресеты сторонних провайдеров остаются в `ai-presets.js` как выбор пользователя только когда `baseURLAI` не заблокирован админом; в блокированном режиме они не показываются.
- Принудительные (admin) значения см. `ADMIN-VS-USER.md`.
- У существующих пользователей `syncSetting` из БД объединяется с дефолтами (`app/lib/get-config.js`), поэтому новые поля (`cloudApiUrl`, `autoSync`) подхватываются, а явно сохранённые значения не затираются (кроме admin-locked).
