# Serial и Telnet

## Последовательный порт

Выберите serial-закладку и порт, видимый ОС backend. Согласуйте скорость, биты данных, parity, stop bits и flow control с документацией устройства. Ошибка порта может означать занятость, отсутствие драйвера или прав, а не сбой закладки.

В Web путь к serial-порту относится к хосту backend, не к компьютеру браузера. Поддержка native serial не означает сертификацию физического адаптера. Сначала используйте безопасный read-only сценарий производителя; команды управления промышленным оборудованием не проверяйте наугад.

## Telnet

Создайте Telnet-закладку с разрешённым адресом и фактическим портом службы. Telnet не шифрует соединение; используйте только контролируемую сеть/защищённый маршрут и не передавайте чувствительные учётные данные. Если сервер поддерживает SSH, предпочтите SSH.

Deep links `serial://` и `telnet://` обрабатываются только при разрешённой ассоциации ОС. Они не передают автоматически права на порт или пароль профиля; machine GUI подтверждает контекст отдельно.
