# Настройки и расположение данных

Пользователь меняет тему, горячие клавиши, шрифты, параметры терминала и соединений в рамках административной политики. В обычном режиме могут настраиваться состав панели, quick commands и прокси соединения.

Admin policy принудительно применяет управляемые значения при чтении/сохранении/старте, не только скрывает форму. К ним относятся sync endpoint, AI endpoint, MCP, обновления, отчёты и некоторые startup/proxy-настройки. Правка локальной БД не является поддерживаемым обходом.

Точная таблица ключей и переменных: [ADMIN-VS-USER.md](../ADMIN-VS-USER.md). Значения по умолчанию: [DEFAULTS.md](../DEFAULTS.md). Исторические QA-заметки в этих документах не отменяют [ограничения версий](Versions.md).

## Данные

Обычный Desktop использует каталог `anubis`: Windows `%APPDATA%\anubis`, macOS `~/Library/Application Support/anubis`, Linux `~/.config/anubis`. `DATA_PATH` меняет путь в поддерживающем его режиме; это не команда миграции и не универсальный override защищённого machine host.

При первом запуске пустого нового каталога предусмотрено копирование совместимого старого `electerm`-профиля. Старое имя оставлено ради совместимости; исходные данные не перемещаются и не удаляются. Наличие реальных данных препятствует миграции; ошибка копирования не должна открывать пустую БД как будто всё успешно.

Machine host хранит SYSTEM отдельно от пользовательского профиля и использует защищённую native-конфигурацию. Не направляйте GUI-кэши на профиль worker и не переносите ключи между Windows accounts.
