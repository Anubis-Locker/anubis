# SSH, SFTP и FTP

## SSH

Создайте SSH-закладку и укажите адрес, порт, пользователя и поддерживаемый способ входа: пароль, ключ, agent или другой доступный в форме механизм. Файл ключа и текст ключа — разные варианты; путь должен быть доступен процессу, выполняющему подключение, а не обязательно браузеру оператора.

Перед первым подключением сверяйте host fingerprint по независимому каналу. При изменении ключа выясните причину, не принимайте его автоматически. Прокси и SSH-туннель настраивайте для разрешённого маршрута; они не создают учётную запись на сервере.

## SFTP

Откройте файловую панель SSH-сеанса. Выберите удалённый каталог и выполните тестовую передачу несекретного файла. Права на чтение/запись определяются удалённой SSH-учётной записью. Не путайте локальную сторону managed-backend с диском компьютера, на котором открыт браузер.

Операции удаления и перезаписи требуют отдельного внимания; сначала проверьте путь и выбранную вкладку. История передач помогает отличить завершённую операцию от ещё выполняющейся.

## FTP

Для FTP создайте отдельную закладку нужного типа. Обычный FTP не обеспечивает конфиденциальность как SSH/SFTP: не используйте его для секретов в недоверенной сети. Не обещайте FTPS или произвольный серверный режим без проверки конкретной сборки и параметров формы.
