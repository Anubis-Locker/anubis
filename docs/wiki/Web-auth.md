# Web-вход, сессии и вкладки сайтов

Standalone Web сохраняет собственную аутентификацию: approval устройства её не заменяет. В managed Web **Open device** обменивает одноразовый билет на защищённую браузерную cookie; административный токен не должен попадать в URL.

Скопированный HTTPS-адрес устройства не переносит вход в другой браузер/incognito. Там снова откройте админ-панель и используйте Open device. При установленном пароле профиля потребуется ещё и этот пароль.

Срок входного билета в 30 секунд — не срок нормальной работы браузерной сессии. Новый вход ожидаем после выхода, отзыва, истечения сессии, смены пароля или перезапуска gateway с сессиями в памяти. Постоянная потеря входа без этих причин требует диагностики.

## HTTP/HTTPS — особый случай

Вкладка сайта в Web использует iframe браузера оператора, его cookies и сетевую доступность. **Open** открывает отдельную вкладку того же браузера оператора. Ни одно действие не запускает Chrome на удалённом Windows-хосте.

Встраивание может блокироваться `X-Frame-Options`, CSP `frame-ancestors` или mixed content для HTTP внутри HTTPS. Не снимайте защиту сайта и не отключайте TLS ради iframe; используйте Open, если обычное открытие разрешено.

Native machine GUI имеет отдельный изолированный website guest: [технический контракт](../EMBEDDED-WEBSITES.md). Он не наследует привилегии SYSTEM и не реализует PRO Browser Control.
