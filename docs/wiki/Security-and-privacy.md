# Безопасность и приватность

Разрешённый доступ состоит из отдельных границ: устройство, Windows-контекст, профиль приложения, серверный протокол и MCP. Успех одной проверки не отменяет остальные.

Сверяйте fingerprint при approval и host key при SSH. Используйте TLS и отдельные сильные секреты. Не передавайте пароль в deep link, командной строке, screenshot или issue. Не публикуйте MCP/management-токен даже после закрытия вкладки.

Данные профиля могут зависеть от OS keychain. Не выдавайте права на защищённый machine-каталог обычным пользователям и не копируйте ключи между user/SYSTEM. Пароль приложения не превращает администратора ОС в недоверенную песочницу: локальный администратор способен менять ПО.

## Сетевые данные

В admin-policy по умолчанию предусмотрены startup heartbeat и отчёты об ошибках. Они включают идентификатор установки и технические сведения; stack/error могут содержать чувствительные детали. Нельзя обещать «никаких исходящих запросов». Действующие параметры и состав: [ADMIN-VS-USER.md](../ADMIN-VS-USER.md).

Sync передаёт выбранные данные провайдеру; AI — содержимое запросов настроенному endpoint. Проверяйте настройки и доверие к оператору сервиса. Managed gateway терминирует TLS и видит авторизованный трафик.

## Сообщение об уязвимости

Не публикуйте действующие credentials, эксплуатационные детали против чужих систем или полную приватную конфигурацию в обсуждении. Для первого конфиденциального контакта используйте `support@anubis.locker` без секретов; согласуйте безопасный канал передачи подробностей. Не предполагайте, что private vulnerability reporting уже включён.
