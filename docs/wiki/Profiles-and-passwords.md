# Профили, шифрование и пароли

Слово «профиль» встречается в разных контекстах. **Profiles** в настройках — шаблоны параметров подключения. **Профиль данных приложения** хранит закладки и настройки. **Windows workspace** выбирает OS-контекст backend. Это не взаимозаменяемые сущности.

| Секрет | Для чего нужен |
| --- | --- |
| Пароль приложения | Защита данных конкретного профиля |
| Windows/RDP/SSH-пароль | Вход в соответствующую ОС или службу |
| Management-токен | Админ-панель управления |
| Web-пароль/JWT | Вход в конкретный standalone Web |
| MCP-токен | Доступ доверенного MCP-клиента |
| Пароль синхронизации | Защита поддерживаемых синхронизируемых данных |

Один секрет не заменяет другой. Администратор gateway не получает возможности извлечь либо сбросить пароль приложения. Для существующего защищённого профиля пароль нужно получить у владельца.

Зашифрованные значения связаны с OS keychain. Ошибка расшифровки — причина остановить вход/инициализацию и восстановить правильную учётную запись и доступ к ключам, а не признать профиль новым. Не удаляйте ключи и БД ради обхода ошибки.

В source-кандидате native действие **SYSTEM password** требует совместимого защищённого broker/helper и явного UAC. Изменение установленного пароля требует прежнего пароля; первоначальная настройка разрешена лишь для действительно неинициализированного читаемого профиля. Это не удалённый reset API.
