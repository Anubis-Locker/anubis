# Desktop, standalone Web и managed-device Web

| Режим | Где работают backend и подключения | Как войти |
| --- | --- | --- |
| Desktop | На компьютере с Desktop | Локальный профиль и его защита |
| Windows native machine GUI | На локальной машине, в явно выбранном доступном workspace | Защищённый локальный broker и проверки контекста/пароля |
| Standalone Web | На хосте отдельного Web-экземпляра | Собственная Web-аутентификация |
| Managed-device Web | На одобренном устройстве; HTTP/HTTPS-сайты — исключение | Админ-панель → Open device, затем при необходимости пароль профиля |

Native GUI не содержит выбора произвольного удалённого managed-устройства по UUID. SYSTEM workspace — служебный профиль, а не экран пользователя. Для рабочего стола нужны RDP/VNC.

В Web сайт HTTP/HTTPS открывается в iframe браузера оператора. Кнопка **Open** также открывает браузер оператора. Запросы сайта не меняют сеть на сеть managed-хоста.

В совместимом native machine GUI отдельная HTTP/HTTPS-вкладка может использовать изолированный Chromium guest. Он принадлежит интерактивному GUI, не наследует SYSTEM-права выбранного backend и не равен Browser Control.

Семь PRO-пунктов не реализуют плагины или удалённый Chrome: [ограничения](Versions.md).
