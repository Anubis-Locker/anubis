# Формат прокси и область действия

Прокси направляет поддерживаемое соединение через промежуточный сервер. Это не SSH jump host, не reverse proxy перед Web и не автоматическая смена сети HTTP/HTTPS-вкладки браузера.

## Поля и формат

Форма строит URL из типа, адреса, порта и, при наличии обоих полей, имени/пароля прокси. Типы формы: HTTP, HTTPS, SOCKS4 и SOCKS5. Примеры без credentials:

```text
http://proxy.example:8080
https://proxy.example:8443
socks4://proxy.example:1080
socks5://proxy.example:1080
```

Указывайте фактический порт явно; bare `host:port` без схемы — не эквивалент корректного URL. Поддерживаемые схемы зависят от конкретного потребителя, а не только от выпадающего списка.

Реквизиты вводите только в предназначенные поля, не в argv или опубликованный URL. В текущем `buildProxyString` специальные символы credentials не percent-encode автоматически; совместимость паролей с `@`, `:`, `/`, `%` нельзя обещать. При ошибке разбора не раскрывайте полный URL в issue: он может содержать секрет.

## Приоритет

Для клиента, использующего `get-proxy`, непустой строковый proxy конкретной вкладки имеет приоритет. Иначе применяется глобальный proxy, только если включён `enableGlobalProxy` и задан строковый адрес. Пустое поле соединения не является переключателем «обойти глобальный proxy».

Административная политика может задавать и блокировать глобальный proxy. Отдельный proxy соединения сохраняет собственную семантику; управляемая настройка не означает системный сетевой firewall.

## Не все транспорты одинаковы

HTTP-запросы backend используют `HttpsProxyAgent` либо `SocksProxyAgent`. SSH/TCP имеет отдельный connector `socks.js`: для HTTP он использует CONNECT, для SOCKS — SOCKS client. В его HTTP/HTTPS-ветке вызывается именно `http.request`; отдельного TLS-to-proxy транспорта для HTTPS там нет. **HTTPS proxy для этого SSH/TCP-пути не заявляется рабочим**, даже если тип есть в форме. Не обходите это отключением TLS или пересылкой секретов по незащищённому маршруту.

SOCKS4 и SOCKS5 имеют разные возможности; не считайте их DNS/auth-семантику взаимозаменяемой. Поддержка прокси у API, SSH, FTP и других протоколов должна проверяться раздельно. Proxy backend не проксирует iframe/Open браузера оператора.
