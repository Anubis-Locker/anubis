# Пакет сообщества: подготовлено, не опубликовано

Материалы предназначены для сопровождающих Anubis-Security-Tool. Это оригинальные редакционные заготовки, не сообщения реальных участников и не подтверждение доступности GitHub Discussions.

Публикация разрешается только после завершения функциональных исправлений и отдельного решения сопровождающего. Частная 5.7.3 не должна описываться как уже выпущенная или установленная.

## Категории

| Категория | Формат GitHub | Для чего | Стартовая тема |
| --- | --- | --- | --- |
| 📣 Объявления | Announcements | Проверенные релизы, изменения и ограничения; пишет команда | Что подтверждено для текущего релиза |
| ❓ Вопросы и ответы | Q&A | Конкретные вопросы с отмеченным ответом | Как выбрать Desktop, Web или managed |
| 💡 Идеи | Open-ended discussion | Проблема пользователя, сценарий и критерий пользы | Как улучшить выбор workspace без путаницы |
| 🧭 Практика и руководства | Open-ended discussion | Проверенные инструкции и разборы | Безопасное первое SSH-подключение |
| 💬 Общение | Open-ended discussion | Знакомство, рабочие привычки, обратная связь | Какие задачи вы решаете клиентом |
| 📊 Опросы | Polls | Только решения, по которым команда готова действовать | Какой раздел Wiki уточнить первым |

Q&A не заменяет bug tracker. Баг с воспроизводимыми шагами переносится в issue со ссылкой на обсуждение без дублирования секретных вложений. Уязвимости направляются в приватный канал.

## Темы и маркировка

Для заголовков/поиска полезны темы `desktop`, `web`, `managed-access`, `windows-workspace`, `ssh-sftp`, `remote-desktop`, `mcp`, `sync`, `documentation`. Это предложение тематизации, не обещание отдельной функции «тегов» Discussions.

Публиковать от команды: подпись **FAQ сопровождающих** либо **Сценарий для обсуждения**. В Q&A ответ отмечается после проверки, не автоматически ради статистики.

## Работа с ответами

Сначала уточнять режим и версию, затем давать безопасный следующий шаг. Для непроверенной функции писать «не подтверждено», для PRO-заглушки — «не реализовано». Не обещать срок исправления без решения команды.

Один полезный материал лучше серии пустых сообщений. Начальный набор — приветственная тема, FAQ о режимах и Wiki-навигация; остальные сценарии публикуются по мере готовности. Не создавать подставные аккаунты и не изображать пользовательский спрос.
